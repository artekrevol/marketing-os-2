# Ahrefs MCP Integration Dispatch (Replit)

**Repo:** TekRevol Content Platform (Marketing OS) — Replit
**Objective:** Give ContentForge generation on-demand access to Ahrefs data via MCP — Domain Rating lookups, backlink summaries, keyword data — during draft-section and final-stitch stages. Cache-first architecture with Redis + Postgres persistence. Every call provenanced and unit-tracked against the 400K/month Ahrefs API budget.
**Dispatch type:** Focused integration. Smaller than the plan architecture but introduces MCP as a new protocol pattern to the codebase. Comparable in scope to the SEO Integration + Cut A combined.

## Context

Ahrefs API access is on the existing TekRevol plan (400,000 units/month, currently 11,313 used). API key generated 22 Jul 2026, stored in Replit Secrets as `AHREFS_API_KEY`. A separate MCP-scope key needs to be generated and stored as `AHREFS_MCP_KEY` — dispatcher confirms this before Phase 0 executes.

This dispatch does NOT do bulk data import into SEO OS (that's a separate dispatch after Ahtesham audits the Rank Tracker). This dispatch adds on-demand tool access during content generation so that when the model needs external SEO context, it can query Ahrefs directly rather than relying on stale platform data.

**Architecture:** Ahrefs MCP server acts as data source. Our api-server acts as MCP client. Our api-server ALSO exposes custom tools to Anthropic during generation. When Anthropic invokes one of our tools, we check cache first, hit Ahrefs MCP on cache miss, persist result, return to Anthropic. This gives us cache control, budget enforcement, provenance, and precise tool scoping — none of which we'd have if we passed Ahrefs MCP directly to Anthropic.

**Data flow:**
```
Anthropic API ← [our tools] ← api-server ← [MCP client] ← Ahrefs MCP Server
                                    ↓
                                Redis cache (Upstash)
                                    ↓
                                Postgres cache tables
```

**Three tools exposed to Anthropic:**
- `get_domain_authority(domain)` — cache-first DR/UR lookup, 7-day cache
- `get_backlink_summary(url)` — cache-first backlink profile summary, 24-hour cache
- `get_keyword_data(keyword, country)` — cache-first keyword volume/KD/CPC, 7-day cache

**Per-generation call budget:** 5 tool invocations maximum per generation cycle (draft-section + final-stitch combined). Excess calls fail with clear error message to the model.

**Explicitly out of scope for this dispatch:**
- Bulk Ahrefs data import into `keywords`, `link_targets`, `competitor_insights` (separate dispatch after Ahtesham audit)
- SEO OS Backlinks page or Referring Domains page (separate SEO module workstream)
- Weekly rank refresh via Ahrefs API (separate dispatch after bulk import)
- Content gap analysis or site audit tools (skip for MVP scope)
- Ahtesham-facing admin surface (this dispatch is Marketing-OS-consumer only)

### 1.1 `domain_authority_cache` table

Persistent cache for DR/UR values. Feeds get_domain_authority tool.

```sql
BEGIN;

CREATE TABLE domain_authority_cache (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  brand_id uuid NOT NULL REFERENCES brands(id) ON DELETE restrict,
  domain text NOT NULL,
  dr numeric(5,2),
  ur numeric(5,2),
  ref_domains_count integer,
  backlinks_count integer,
  last_measured timestamptz NOT NULL DEFAULT now(),
  source_provider text NOT NULL DEFAULT 'ahrefs_mcp',
  source_metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (brand_id, domain)
);

CREATE INDEX domain_authority_cache_brand_domain_idx
  ON domain_authority_cache(brand_id, domain);
CREATE INDEX domain_authority_cache_last_measured_idx
  ON domain_authority_cache(last_measured);

COMMIT;
```

Add to `BRAND_SCOPED_TABLES`. Update Drizzle schema in `lib/db/src/schema/`.

Per-call unit consumption tracking. Enables per-brand budget monitoring and admin visibility.

```sql
BEGIN;

CREATE TABLE ahrefs_mcp_usage (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  brand_id uuid NOT NULL REFERENCES brands(id) ON DELETE restrict,
  called_at timestamptz NOT NULL DEFAULT now(),
  tool_name text NOT NULL,
  params_hash text NOT NULL,
  cache_hit boolean NOT NULL DEFAULT false,
  units_consumed integer NOT NULL DEFAULT 0,
```

### 2.2 `AhrefsMCPClient` class

File: `lib/integrations/ahrefs/src/mcp-client.ts`

Responsibilities:
- Manage connection to Ahrefs MCP server via SSE transport
- Handle authentication via `AHREFS_MCP_KEY` bearer token
- Expose typed tool invocation methods
- Track raw unit consumption per call
- Retry logic on transient failures (max 2 retries with exponential backoff)
- Clear error surfacing on non-recoverable errors

Interface:

```typescript
export interface MCPCallResult<T> {
  success: boolean;
  data?: T;
  error?: string;
  unitsConsumed: number;
  latencyMs: number;
}

export class AhrefsMCPClient {
  constructor(config: { mcpKey: string; mcpUrl: string });
  
  async callDomainAuthority(domain: string): Promise<MCPCallResult<{
    dr: number;
    ur: number;
    refDomainsCount: number;
    backlinksCount: number;
  }>>;
  
  async callBacklinkSummary(url: string): Promise<MCPCallResult<{
    totalBacklinks: number;
    referringDomains: number;
    dofollowBacklinks: number;
    topAnchors: Array<{ anchor: string; count: number }>;
  }>>;
  
  async callKeywordData(keyword: string, country: string): Promise<MCPCallResult<{
    volume: number;
    keywordDifficulty: number;
    cpc: number;
    parentTopic: string | null;
  }>>;
  
  async close(): Promise<void>;
}
```

## Phase 3 — Cached tool helpers

File: `lib/content-ai/src/tools/ahrefs/`

Three helper functions that Anthropic's tool_use will invoke via the api-server. Each implements cache-first, MCP-fallback logic.

### 3.1 `getDomainAuthority(brandId, domain)`

```typescript
export async function getDomainAuthority(
  brandId: string,
  domain: string
): Promise<DomainAuthorityResult> {
  // 1. Normalize domain (strip protocol, www, trailing slash)
  const normalizedDomain = normalizeDomain(domain);
  
  // 2. Check Redis cache first (5-minute TTL for hot cache)
  const redisKey = `ahrefs:dr:${brandId}:${normalizedDomain}`;
  const cached = await redis.get(redisKey);
  if (cached) {
    await logUsage(brandId, 'get_domain_authority', normalizedDomain, {
      cacheHit: true, source: 'redis'
    });
    return JSON.parse(cached);
  }
  
  // 3. Check Postgres cache (7-day staleness threshold)
  const dbCached = await withBrandScope(brandId, async (db) => {
    return db.select().from(domainAuthorityCache)
      .where(and(
        eq(domainAuthorityCache.brandId, brandId),
        eq(domainAuthorityCache.domain, normalizedDomain),
        gte(domainAuthorityCache.lastMeasured, subDays(new Date(), 7))
      )).limit(1);
  });
  
  if (dbCached[0]) {
    // Refresh Redis
    await redis.set(redisKey, JSON.stringify(dbCached[0]), 'EX', 300);
    await logUsage(brandId, 'get_domain_authority', normalizedDomain, {
      cacheHit: true, source: 'postgres'
    });
    return dbCached[0];
  }
  
  // 4. Cache miss — call MCP
  const mcpResult = await ahrefsMCPClient.callDomainAuthority(normalizedDomain);
  
  if (!mcpResult.success) {
    await logUsage(brandId, 'get_domain_authority', normalizedDomain, {
      cacheHit: false, error: mcpResult.error, unitsConsumed: mcpResult.unitsConsumed
    });
    throw new Error(`Ahrefs DR lookup failed: ${mcpResult.error}`);
  }
  
  // 5. Persist to Postgres cache
  await withBrandScope(brandId, async (db) => {
    await db.insert(domainAuthorityCache).values({
      brandId, domain: normalizedDomain, ...mcpResult.data,
      sourceProvider: 'ahrefs_mcp', sourceMetadata: { latencyMs: mcpResult.latencyMs }
    }).onConflictDoUpdate({
      target: [domainAuthorityCache.brandId, domainAuthorityCache.domain],
      set: { ...mcpResult.data, lastMeasured: new Date() }
    });
  });
  
  // 6. Refresh Redis
  await redis.set(redisKey, JSON.stringify(mcpResult.data), 'EX', 300);
  
  // 7. Log usage
  await logUsage(brandId, 'get_domain_authority', normalizedDomain, {
    cacheHit: false, source: 'mcp', unitsConsumed: mcpResult.unitsConsumed
  });
  
  return mcpResult.data;
}
```

### 3.2 `getBacklinkSummary(brandId, url)`

Same pattern as 3.1, but:
- Cache TTL: 24 hours (backlinks change faster than DR)
- Redis TTL: 5 minutes
- Uses Redis-only cache (no Postgres persistence unless dispatcher requests — backlink data is volatile)
- Returns backlink profile summary, not individual backlinks

### 3.3 `getKeywordData(brandId, keyword, country)`

Same pattern:
- Cache TTL: 7 days
- Uses Redis-only cache (keyword data cached as JSON string)
- Cache key includes country to avoid cross-country collisions

### 3.4 Common `logUsage` helper

Logs every call attempt to `ahrefs_mcp_usage` table:

```typescript
async function logUsage(brandId: string, toolName: string, params: string, metadata: {
  cacheHit: boolean;
  source?: 'redis' | 'postgres' | 'mcp';
  unitsConsumed?: number;
  error?: string;
  projectId?: string;
}) {
  await withBrandScope(brandId, async (db) => {
    await db.insert(ahrefsMcpUsage).values({
      brandId,
      toolName,
      paramsHash: hashParams(params),
      cacheHit: metadata.cacheHit,
      unitsConsumed: metadata.unitsConsumed ?? 0,
      responseStatus: metadata.error ? 'error' : 'success',
      errorMessage: metadata.error,
      projectId: metadata.projectId,
      metadata: { source: metadata.source }
    });
  });
  
  // Also emit provenance row for downstream tracing
  await emitProvenance({
    entityType: 'ahrefs_mcp_call',
    entityId: metadata.projectId || 'system',
    sourceModule: 'content-ai',
    sourceProvider: 'ahrefs_mcp',
    generationMethod: toolName,
    metadata: { cacheHit: metadata.cacheHit, source: metadata.source }
  });
}
```

### 4.2 Tool execution handler

File: `lib/content-ai/src/tools/ahrefs/handler.ts`

```typescript
export async function executeAhrefsTool(
  brandId: string,
  projectId: string,
  toolUse: { name: string; input: any; id: string },
  callBudget: { remaining: number; used: number }
): Promise<{ toolResultBlock: any; budgetUsed: number }> {
  
  // Enforce call budget
  if (callBudget.remaining <= 0) {
    return {
      toolResultBlock: {
        type: 'tool_result',
        tool_use_id: toolUse.id,
        content: `Error: Ahrefs tool budget exceeded for this generation (${callBudget.used}/5 calls used). Continue without additional Ahrefs data.`,
        is_error: true
      },
      budgetUsed: 0
    };
  }
  
  try {
    let result: any;
    switch (toolUse.name) {
      case 'get_domain_authority':
        result = await getDomainAuthority(brandId, toolUse.input.domain);
        break;
      case 'get_backlink_summary':
        result = await getBacklinkSummary(brandId, toolUse.input.url);
        break;
      case 'get_keyword_data':
        result = await getKeywordData(brandId, toolUse.input.keyword, toolUse.input.country || 'us');
        break;
      default:
        throw new Error(`Unknown Ahrefs tool: ${toolUse.name}`);
    }
    
    return {
      toolResultBlock: {
        type: 'tool_result',
        tool_use_id: toolUse.id,
        content: JSON.stringify(result)
      },
      budgetUsed: 1
    };
  } catch (err) {
    return {
      toolResultBlock: {
        type: 'tool_result',
        tool_use_id: toolUse.id,
        content: `Error: ${err.message}. Continue without this data.`,
        is_error: true
      },
      budgetUsed: 1 // Failed calls still count against budget
    };
  }
}
```

### 4.3 Update `callAnthropicRaw` to support tool loop

Extend the function at line ~102 of `artifacts/api-server/src/routes/ai/index.ts`:

```typescript
async function callAnthropicRaw(body: Record<string, unknown>, options?: {
  toolContext?: {
    brandId: string;
    projectId: string;
    enabledTools: 'ahrefs' | 'none';
  };
}): Promise<any> {
  const enabledTools = options?.toolContext?.enabledTools === 'ahrefs'
    ? AHREFS_TOOL_DEFINITIONS
    : undefined;
  
  const callBudget = { remaining: 5, used: 0 };
  let currentBody = { ...body, tools: enabledTools };
  let messages = [...(body.messages as any[])];
  
  for (let iteration = 0; iteration < 10; iteration++) {
    const response = await fetch(ANTHROPIC_URL, {
      method: 'POST',
      headers: { /* existing headers */ },
      body: JSON.stringify({ ...currentBody, messages })
    });
    
    if (!response.ok) {
      throw new Error(`Anthropic ${response.status}: ${(await response.text()).slice(0, 500)}`);
    }
    
    const data = await response.json();
    
    // Check for tool_use in response
    const toolUseBlocks = data.content?.filter((c: any) => c.type === 'tool_use') ?? [];
    
    if (toolUseBlocks.length === 0) {
      // Model finished — return final response
      return data;
    }
    
    // Execute all tool uses in parallel
    const toolResults = await Promise.all(
      toolUseBlocks.map(async (toolUse: any) => {
        const { toolResultBlock, budgetUsed } = await executeAhrefsTool(
          options!.toolContext!.brandId,
          options!.toolContext!.projectId,
          toolUse,
          callBudget
        );
        callBudget.remaining -= budgetUsed;
        callBudget.used += budgetUsed;
        return toolResultBlock;
      })
    );
    
    // Append assistant message with tool_use and user message with tool_results
    messages.push({ role: 'assistant', content: data.content });
    messages.push({ role: 'user', content: toolResults });
  }
  
  throw new Error('Tool loop exceeded 10 iterations');
}
```

### 6.2 Architect review

`git show --stat HEAD` before declaring complete. Treat architect feedback as authoritative.

Three areas to scrutinize:

**Tool loop termination.** The tool_use / tool_result loop has a hard cap of 10 iterations. Verify the cap actually prevents runaway loops when the model gets confused and keeps requesting tools. Also verify graceful degradation when tool calls fail — model should continue with error-informed responses, not crash the generation.

**Cache invalidation edge cases.** Domain normalization must be consistent between cache write and cache read. Verify `statista.com`, `Statista.com`, `www.statista.com`, and `https://statista.com/` all resolve to the same cache key. Verify Postgres UNIQUE constraint doesn't reject legitimate cross-brand entries for the same domain.

**Unit consumption accuracy.** The dispatch estimates units per tool call based on Ahrefs' published rates. Verify actual consumption in Ahrefs UI matches recorded units in `ahrefs_mcp_usage`. Divergence > 20% indicates the tracking logic needs adjustment.

## Operational notes

- **Order strict:** Phase 1 → 2 → 3 → 4 → 5 → 6. Each phase has pause point for dispatcher review.

- **Pause points:**
  1. After Phase 0 survey (verify secrets, endpoints, dependencies)
  2. After Phase 1 completes (schema check)
  3. After Phase 2 completes (MCP client working)
  4. After Phase 3 completes (cache helpers working)
  5. After Phase 4 completes (full generation with tools working end-to-end)
  6. After Phase 6 completion, before declaring done

- **Cost hedges:**
  - Per-generation budget: 5 tool calls maximum
  - Monthly budget: 400K units (tracked in ahrefs_mcp_usage, alerts at 60/80/95%)
  - Cache-first architecture: 60%+ cache hit rate expected after warm-up
  - Redis cache 5 min TTL, Postgres cache 7 days (DR), Redis-only 24 hours (backlinks)

- **What this dispatch does NOT do:**
  - Bulk data import (organic keywords, top pages, competitors, backlinks)
  - SEO OS UI surfaces (Backlinks page, Referring Domains page)
