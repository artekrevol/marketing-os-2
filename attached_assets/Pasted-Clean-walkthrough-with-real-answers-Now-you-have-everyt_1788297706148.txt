## What could go wrong

**Most likely: missing environment variable.** If a Scheduled Deployment run fails with "cannot connect to database" or similar, the specific env var isn't set correctly on that deployment. Check that DATABASE_URL and REDIS_URL are configured for the Scheduled Deployment, not just present in general Secrets.

**Second most likely: build command fails.** If the workspace build fails during Scheduled Deployment creation, you'll see a build error before the run even happens. Report the specific error to the agent — probably a pnpm workspace resolution issue.

**Third possibility: dispatcher succeeds but worker doesn't process.** Reserved VM logs would show no evidence of the job being picked up. This would surface as an architectural issue we'd need to diagnose — but based on the agent's earlier fix work, this is unlikely.

**Don't proceed to Phase 4 if any of the four Scheduled Deployments fail to test-run successfully.** Get all four green first, then move to backfill.
