**On the database connection question — don't wire up Supabase from this Replit container.** Two reasons:

The container is the dev environment. Pointing it at production data crosses a boundary that's hard to uncross. Even read-only access to prod from a dev container creates a path where someone could accidentally run a destructive query and not realize they were on prod. Worth the friction of running these queries from somewhere with explicit prod intent — the Supabase SQL editor in the dashboard is the right place.

You only need to run them once for the retrospective. Building durable infrastructure for a one-off task is overhead. If the retrospective surfaces a need for an ongoing dashboard, that becomes Sprint 9's Performance Monitor work — purpose-built, not a shortcut.

What to do instead: paste the four queries directly into the Supabase SQL editor, run them as a logged-in admin (your auth, not a service role), copy the results into a doc, walk into the retrospective with that doc. Five minutes of manual work; zero new permanent connections to maintain.
