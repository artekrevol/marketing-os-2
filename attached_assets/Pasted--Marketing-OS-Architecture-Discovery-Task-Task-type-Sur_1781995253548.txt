## Section B — Database and schema

The previous architectural context for this dispatch was that the platform sat on Supabase. **That context is stale.** Do not assume Supabase. Report what is actually wired up.

1. Identify the current database. Look for clues in env example files (`.env.example`, `.env.sample`), connection strings in code, and `package.json` dependencies. Report:
   - Database engine (Postgres / MySQL / SQLite / etc.)
   - Hosting (Neon / Railway / Supabase / self-hosted / etc.) — check for provider-specific connection-string formats
   - Connection-string env var name
2. Identify the ORM by checking dependencies. Report:
   - ORM name and version
   - Where the schema files live (full paths)
   - Where migrations live
   - Schema-management command (e.g., `drizzle-kit push`, `prisma migrate`)
3. Run a search for every table definition. Use a search appropriate to the ORM:
   - For Drizzle: `grep -rEn "^export const \w+ = (pg|mysql|sqlite)Table" --include="*.ts"`
   - For Prisma: `cat prisma/schema.prisma` and list `model` definitions
   - For TypeORM: search for `@Entity` decorators
4. List every table found, with: name, file location, and a one-line description of what it stores based on its columns.
5. Identify multi-tenancy:
   - Is there a `brand_id` column on any tables? If so, list which.
   - Is there a `users` table? Show its column definitions.
   - Are there any Row-Level Security policies, brand-scoping helpers (`withBrandScope`, `currentBrand`, similar), or middleware that filters by brand/user?
6. Report whether any keyword, ranking, competitor, or SEO-related tables already exist — even partially scaffolded.
