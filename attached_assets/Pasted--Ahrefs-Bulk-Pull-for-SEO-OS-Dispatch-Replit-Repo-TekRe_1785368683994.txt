# Ahrefs Bulk Pull for SEO OS Dispatch (Replit)

**Repo:** TekRevol Content Platform (Marketing OS) — Replit
**Objective:** One-time comprehensive bulk pull of Ahrefs data into SEO OS as foundational data. Organic keywords (all ~2,731 with automated priority classification), top pages (~200-500), organic competitors (top 20), referring domains (~7,200 with DR/UR). Coexists with existing DataForSEO data via source attribution. Enables the SEO team to work against a richer keyword corpus and enables the Planner AI's citation validation to query real DR values from the platform.
**Dispatch type:** Foundational data import. Larger than the MCP integration but smaller than the plan architecture. Comparable in scope to the SEO Dashboard migration.

## Context

The Ahrefs MCP integration shipped (Phases 1-6) — provides on-demand DR/backlink/keyword lookups during content generation. This dispatch is different: bulk REST API pull of the entire Ahrefs data footprint for tekrevol.com into SEO OS tables.

**Why bulk vs. on-demand:**
- SEO OS Keywords page needs comprehensive coverage, not just what content generation happens to query
- Planner AI's citation validation benefits from a warm domain_authority_cache seeded with ~7,200 pre-known DR values rather than hitting MCP for every citation URL
- Ahtesham's SEO strategy work needs the full keyword corpus available, not just the migrated 425 from the SEO Dashboard

**Real API field structure verified via probe (2026-07-23):**
- Organic keywords: `keyword`, `volume`, `best_position`, `keyword_difficulty`, `cpc`, `best_position_url`, `sum_traffic`, plus 5 intent booleans (`is_informational`, `is_transactional`, `is_commercial`, `is_navigational`, `is_branded`)
- Top pages: `url`, `sum_traffic`, `keywords`, `value`, `referring_domains`, `ur`, `top_keyword`, `page_type` (hierarchical: `/Article/News_Update`, `/Core_Page/Services_Page`)
- Organic competitors: `competitor_domain`, `keywords_common`, `keywords_competitor`, `domain_rating`, `traffic`, `share`, `pages`
- Referring domains: schema TBD via Phase 0 probe

**Classification decisions locked:**
- `is_branded: true` → hard-drop to P3 regardless of other metrics (off-vertical traffic like Fortnite stats)
- P0: `is_commercial: true` AND `best_position ≤ 10` AND `volume ≥ 300` AND NOT `is_branded`
- P1: (`is_commercial: true` OR `is_transactional: true`) AND `best_position ≤ 20` AND `volume ≥ 100` AND NOT `is_branded`
- P2: `best_position ≤ 30` AND `volume ≥ 50` AND NOT `is_branded`
- P3: everything else including all `is_branded: true`
- `is_high_value_target`: top 20% by `sum_traffic × cpc` across the corpus (excluding branded)

**Conflict resolution locked:**
- Merge preserves original priority in `priority_pre_ahrefs_import` column (auditability)
- Overwrite semantics: heuristic-derived priority replaces existing on import
- Metrics (position, volume, KD) always overwritten with Ahrefs' fresh values
- Ahtesham can bulk-reclassify via SEO OS Keywords page after import if heuristic result feels wrong

**Cost budget:**
- Hard stop at 10,000 units for this entire dispatch (env var `AHREFS_BULK_PULL_MAX_UNITS`)
- Estimated actual consumption: ~2,500-5,000 units across all phases
- Consumption tracked per API call in new `ahrefs_rest_usage` table

**Explicitly out of scope:**
- Backlinks bulk pull (51.9K rows, deferred until SEO OS Backlinks page is designed)
- Content gap analysis (on-demand, better via MCP or REST spot-checks)
- Site audit data (separate workstream)
- SEO OS UI surfaces for imported data (this dispatch is data-only; UI extensions ship as follow-ups)
- Other brands (TekRevol only for this dispatch; ClaimShield/Reverto/CensusFlow follow separately)

### 2.1 Client class

```typescript
export interface AhrefsRestConfig {
  apiKey: string;
  baseUrl: string; // 'https://api.ahrefs.com/v3'
  maxUnitsPerDispatch: number; // hard stop, default 10000
  onUnitsConsumed?: (units: number, total: number) => void;
}

export interface RestCallResult<T> {
  success: boolean;
  data?: T;
  error?: string;
  unitsConsumed: number;
  rowsReturned: number;
  latencyMs: number;
  rateLimited: boolean;
}

export class AhrefsRestClient {
  constructor(config: AhrefsRestConfig);
  
  // Paginated fetch — handles multi-page pulls transparently
  async fetchAllOrganicKeywords(target: string, options: {
    country?: string;
    minVolume?: number;
    maxPosition?: number;
  }): Promise<RestCallResult<OrganicKeywordRow[]>>;
  
  async fetchAllTopPages(target: string, options: {
    country?: string;
    limit?: number;
  }): Promise<RestCallResult<TopPageRow[]>>;
  
  async fetchOrganicCompetitors(target: string, options: {
    country?: string;
    limit?: number;
  }): Promise<RestCallResult<CompetitorRow[]>>;
  
  async fetchAllReferringDomains(target: string, options: {
    minDr?: number;
    limit?: number;
  }): Promise<RestCallResult<ReferringDomainRow[]>>;
  
  // Global units-consumed tracker
  getTotalUnitsConsumed(): number;
  
  // Hard stop check — throws if approaching maxUnitsPerDispatch
  checkBudget(estimatedUnits: number): void;
}
```

### 2.2 Pagination handling

Ahrefs REST returns results in pages (typically 100-1000 rows per call depending on endpoint). Client transparently pages through until all results retrieved:

- Uses `offset` parameter or cursor-based pagination (verify via response inspection in Phase 3)
- Between pages: 250ms delay to respect rate limits
- Reports progress via `onUnitsConsumed` callback
- Aborts if `checkBudget()` fails

### 2.3 Retry logic

- HTTP 429 (rate limit): exponential backoff, max 3 retries
- HTTP 5xx: retry once after 1s delay
- HTTP 4xx (except 429): fail immediately, no retry
- Network errors: retry once after 500ms

### 3.2 Classification heuristic

```typescript
function classifyKeyword(row: OrganicKeywordRow): 'P0' | 'P1' | 'P2' | 'P3' {
  // Hard drop is_branded to P3 regardless of other metrics
  if (row.is_branded) return 'P3';
  
  // P0: commercial + strong position + real volume
  if (
    row.is_commercial &&
    row.best_position <= 10 &&
    row.volume >= 300
  ) return 'P0';
  
  // P1: commercial/transactional intent + reasonable position + moderate volume
  if (
    (row.is_commercial || row.is_transactional) &&
    row.best_position <= 20 &&
    row.volume >= 100
  ) return 'P1';
  
  // P2: broader coverage
  if (
    row.best_position <= 30 &&
    row.volume >= 50
  ) return 'P2';
  
  // P3: everything else
  return 'P3';
}
```

### 3.3 High-value target flag

Computed across the corpus after classification:

```typescript
function markHighValueTargets(rows: OrganicKeywordRow[]): Set<string> {
  const eligible = rows.filter(r => !r.is_branded && r.cpc != null);
  
  const scored = eligible.map(r => ({
    keyword: r.keyword,
    trafficValue: r.sum_traffic * (r.cpc || 0)
  }));
  
  scored.sort((a, b) => b.trafficValue - a.trafficValue);
  
  const cutoff = Math.floor(scored.length * 0.2); // top 20%
  return new Set(scored.slice(0, cutoff).map(s => s.keyword));
}
```

### 3.4 Import with reconciliation

```typescript
async function importKeywords(brandId: string, rows: OrganicKeywordRow[]) {
  const highValueSet = markHighValueTargets(rows);
  
  const CHUNK_SIZE = 100;
  const stats = { inserted: 0, updated: 0, priorityChanged: 0, priorityPreserved: 0 };
  
  for (let i = 0; i < rows.length; i += CHUNK_SIZE) {
    const chunk = rows.slice(i, i + CHUNK_SIZE);
    
    await withBrandScope(brandId, async (db) => {
      for (const row of chunk) {
        const priority = classifyKeyword(row);
        const isHighValue = highValueSet.has(row.keyword);
        
        // Check existing
        const existing = await db.select().from(keywords)
          .where(and(
            eq(keywords.brandId, brandId),
            eq(keywords.keywordText, row.keyword)
          ))
          .limit(1);
        
        const intentFlags = {
          informational: row.is_informational,
          transactional: row.is_transactional,
          commercial: row.is_commercial,
          navigational: row.is_navigational,
          branded: row.is_branded
        };
        
        if (existing[0]) {
          // Merge: preserve existing priority in backup column, overwrite priority + metrics
          const originalPriority = existing[0].priority;
          const priorityChanged = originalPriority !== priority;
          
          await db.update(keywords).set({
            priority,
            priorityPreAhrefsImport: originalPriority,
            ahrefsBestPosition: row.best_position,
            ahrefsKeywordDifficulty: row.keyword_difficulty,
            ahrefsSumTraffic: row.sum_traffic,
            ahrefsBestPositionUrl: row.best_position_url,
            ahrefsIntentFlags: intentFlags,
            ahrefsCpc: row.cpc,
            ahrefsLastUpdated: new Date(),
            isBranded: row.is_branded,
            isHighValueTarget: isHighValue
          }).where(eq(keywords.id, existing[0].id));
          
          stats.updated++;
          if (priorityChanged) stats.priorityChanged++;
          else stats.priorityPreserved++;
        } else {
          // Insert new
          await db.insert(keywords).values({
            brandId,
            keywordText: row.keyword,
            priority,
            searchVolume: row.volume,
            ahrefsBestPosition: row.best_position,
            ahrefsKeywordDifficulty: row.keyword_difficulty,
            ahrefsSumTraffic: row.sum_traffic,
            ahrefsBestPositionUrl: row.best_position_url,
            ahrefsIntentFlags: intentFlags,
            ahrefsCpc: row.cpc,
            ahrefsLastUpdated: new Date(),
            isBranded: row.is_branded,
            isHighValueTarget: isHighValue,
            isActive: true,
            trackDaily: false // Ahtesham promotes to daily tracking selectively
          });
          
          stats.inserted++;
        }
      }
    });
  }
  
  return stats;
}
```
