**Repo:** TekRevol Content Platform (Marketing OS) — Replit
**Supersedes:** the earlier "Content Quality Fix Dispatch FINAL." That dispatch assumed file-based asset loading from `/data/`. The Shared Data Layer has since shipped; this v2 uses the database-backed pattern instead. Send v2 only; ignore v1.

**Regression targets:**
- Primary: project `821e5c72-0cb7-400e-83f4-77d533b445a8` (Austin app development cost blog)
- Secondary: project `04cc54c1-8aef-4bd3-acc6-0dc3dd2bb4e9` (dog training app development cost blog)

**Dispatch type:** Single sequential change. Schema → ingestion → generation rules → validators → regression. Eight phases.

---

## What this dispatch fixes

Two audited blogs surfaced four classes of failure: wrong proof (internal financials and per-project dollars used as authority), wrong structure (duplicate H2s, prose where lists belong, missing FAQ blocks), wrong substance (cost guides missing hourly rates, team models, maintenance breakdowns), and wrong tone (brand mentions stacked 14+ times per piece, scattered CTAs, advertorial voice).

After this dispatch, regenerating either audited piece must produce a structurally valid, asset-validated article that opens with a direct answer in the first 100 words, proves expertise through engineering specifics rather than dollar amounts, and uses only TekRevol assets that exist in the canonical database tables. Validators block ship on every one of these requirements.

## Phase 1 — Schema: asset tables

Three new tables. Scoped transactional DDL only — no blanket `drizzle-kit push` (the schema drift from `user_roles`/`page_events`/`playbook_sections` remains untouched).

### 1.1 `reviews_bank_entries` — the testimonial corpus

83 reviews from Clutch, attributed by name + company, queryable by ICP and vertical.

```sql
CREATE TABLE "reviews_bank_entries" (
  "id"                uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "brand_id"          uuid NOT NULL REFERENCES "brands"("id") ON DELETE restrict,
  "reviewer_name"     text NOT NULL,
  "reviewer_role"     text,
  "company"           text NOT NULL,
  "company_industry"  text,
  "project_name"      text,
  "quote_excerpt"     text NOT NULL,        -- the short displayable quote
  "quote_full"        text,                  -- full transcript when available
  "rating"            numeric(3,1),          -- 0.5 to 5.0
  "source_url"        text,                  -- Clutch profile URL
  "date_published"    date,
  "icp"               integer,               -- 1-4 (passion founder | operator | tech pro | enterprise)
  "vertical"          text,                  -- healthcare | fintech | real_estate | etc.
  "cost_bucket"       text,                  -- under_50k | 50k_to_200k | over_200k
  "outcome_metrics"   jsonb DEFAULT '{}'::jsonb,
  "is_confidential"   boolean NOT NULL DEFAULT false,  -- true = exclude from generation (the 0.5 and 1.0 reviews)
  "confidential_reason" text,                -- 'critical_review' | 'client_requested' | etc.
  "imported_at"       timestamptz NOT NULL DEFAULT now(),
  "last_verified_at"  timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT "reviews_bank_entries_reviewer_company_uq"
    UNIQUE ("brand_id", "reviewer_name", "company")
);
CREATE INDEX "rbe_brand_icp_idx"      ON "reviews_bank_entries" ("brand_id", "icp")          WHERE "is_confidential" = false;
CREATE INDEX "rbe_brand_vertical_idx" ON "reviews_bank_entries" ("brand_id", "vertical")     WHERE "is_confidential" = false;
CREATE INDEX "rbe_brand_confidential_idx" ON "reviews_bank_entries" ("brand_id", "is_confidential");
```

The confidentiality flag is the *only* gate for testimonial generation. Validators query `WHERE is_confidential = false` always — the gates can't be bypassed by validator code that forgets the filter, because partial indexes only cover non-confidential entries (queries against confidential rows take a slower path, which is acceptable and a safety floor).

### 1.2 `link_targets` — the internal linking file as a queryable corpus

113 URLs from TekRevol's website, classified for ContentForge to query during generation.

```sql
CREATE TABLE "link_targets" (
  "id"                  uuid PRIMARY KEY DEFAULT gen_random_uuid() NOT NULL,
  "brand_id"            uuid NOT NULL REFERENCES "brands"("id") ON DELETE restrict,
  "url"                 text NOT NULL,
  "page_title"          text,
  "page_type"           text NOT NULL,           -- 'home' | 'service' | 'solution' | 'blog' | 'location' | 'case_study' | etc.
  "content_cluster"     text,                    -- 'mobile_app' | 'ai' | 'cloud' | etc.
  "vertical"            text,                    -- 'healthcare' | 'fintech' | null
  "funnel_stage"        text NOT NULL,           -- 'TOFU' | 'MOFU' | 'BOFU'
  "primary_icp"         integer,                 -- 1-4
  "primary_keyword"     text,
  "anchor_variations"   jsonb NOT NULL DEFAULT '[]'::jsonb,  -- array of 3 anchor strings
  "use_for"             text,                    -- guidance description from the linking file
  "is_active"           boolean NOT NULL DEFAULT true,
  "imported_at"         timestamptz NOT NULL DEFAULT now(),
  "last_verified_at"    timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT "link_targets_brand_url_uq" UNIQUE ("brand_id", "url")
);
CREATE INDEX "lt_brand_cluster_idx" ON "link_targets" ("brand_id", "content_cluster") WHERE "is_active" = true;
CREATE INDEX "lt_brand_funnel_icp_idx" ON "link_targets" ("brand_id", "funnel_stage", "primary_icp") WHERE "is_active" = true;
CREATE INDEX "lt_brand_url_lookup_idx" ON "link_targets" ("brand_id", "url") WHERE "is_active" = true;
```

`is_active = false` is the soft-delete path. Validators query against `is_active = true` only. The brand-scoped URL uniqueness prevents the same URL appearing twice per brand.

```sql
CREATE INDEX "lr_brand_pattern_idx" ON "linking_rules" ("brand_id", "trigger_pattern");
```

## Phase 2 — Asset ingestion (admin endpoints + UI)

Two import endpoints, two admin UI surfaces, one set of canonical query helpers. All use the existing patterns from the playbook upload widget.

### 2.1 Reviews bank import

**Endpoint:** `POST /api/admin/reviews-bank/import`
- Auth: admin only.
- Body: array of review objects (matching the schema in 1.1). Upserts by `(brand_id, reviewer_name, company)`. Records each upsert in `module_data_provenance` with `source_module = 'system'`, `generation_method = 'import'`, `metadata = { source_file: 'reviews_bank.json', count: N }`.

**Endpoint:** `GET /api/admin/reviews-bank` — list all entries for the active brand, with confidential flag visible.

**Endpoint:** `PATCH /api/admin/reviews-bank/:id` — edit a single entry (typically to flip `is_confidential` or update outcome metrics). Each edit emits a provenance row tagged with the editing user.

**Endpoint:** `DELETE /api/admin/reviews-bank/:id` — soft-delete (sets a flag). Provenance row emitted.

**Admin UI page:** `/admin/reviews-bank` in ContentForge. List view sortable by ICP, vertical, confidentiality. Import button takes the `reviews_bank.json` file directly. Inline edit for confidentiality toggle.

### 2.2 Link targets import

**Endpoint:** `POST /api/admin/link-targets/import`
- Auth: admin only.
- Body: structured object with `link_targets[]` and `linking_rules[]` arrays. Upserts both tables. Records in provenance.

**Endpoint:** `GET /api/admin/link-targets` — list view for the active brand.

**Endpoint:** `PATCH /api/admin/link-targets/:id` — update entry. Useful when a URL retires or a page's funnel stage changes.

**Endpoint:** `DELETE /api/admin/link-targets/:id` — soft-delete (sets `is_active = false`).

**Admin UI page:** `/admin/link-targets` in ContentForge. Table view filterable by cluster, funnel stage, ICP. Import button takes the `internal_linking.xlsx` file (server-side parse using the existing xlsx library used elsewhere in the platform).

The DataForSEO client is already wired from the SEO module integration. This dispatch's needs require two additional behaviors at the research stage:

After the existing SERP Live Advanced call returns top-10, scan for missing-element signals and set required-content flags on the project:

## Phase 5 — Generation rules (16 bundles)

### 5.1 Brand-mention ratio (funnel-differentiated)

Count branded mentions ("TekRevol", "our team", "our work", "our clients", "we") as ratio to non-branded sentences.

| Funnel | Max ratio |
|---|---|
| TOFU | 1:12 |
| MOFU | 1:8 |
| BOFU | 1:5 |

Exceeds threshold → block ship via `validation.brand_mention_passes = false`.

### 5.2 Direct-answer + closing reinforcement (hard)

**Opening:** first 100 words MUST contain primary keyword + 2–3-sentence direct answer.
**Closing:** summary or FAQ block MUST contain exact-match primary keyword again.
Either fails → block ship.

### 5.3 Competitive completeness

Driven by Phase 3.1 flags. If a flag is set, the schema field is required. Missing → block ship.

### 5.4 Heading hygiene

H1 unique. No duplicate H2s. No duplicate H3s within parent. Valid nesting. Block on duplicates.

### 5.5 Citation grounding + authority floor

- Every URL in `statistics_used` and `external_authority_citations` → HTTP 200 + content match (±5% on numbers). Failures stripped, `verified_live = false`.
- Every stat must have a `year`. `year < current_year - 2` → `flagged_as_stale = true`. Flag inline, don't block.
- **Authority floor:** ≥2 entries in `external_authority_citations` from whitelist (clutch.co, statista.com, bls.gov, gartner.com, mckinsey.com, hbr.org, .gov, .edu, etc.). Below 2 → block ship.

### 5.6 Content-type integrity

CTAs only in `cta_block`. Body reads vendor-neutral. >1 CTA detected mid-body → block ship.

### 5.7 Author byline

Fixed: "By the TekRevol team." Credentials from `getCredentialBlock()`. Bio link `/about`. Top of article.

### 5.8 Visual prompts

For cost/timeline/regional flagged articles, generate `visual_prompts` array. Designer-facing, used by Central Design when producing infographics.

### 5.9 Case-study narrative pivot (the most important rule)

This is the change with the largest impact on perceived quality. Both audits identified it independently.

**Schema-enforced:** `case_studies_cited[]` has no `contract_value` field. The model cannot emit it because nowhere to put it.

**Validation (Phase 6.6):**
- `technical_narrative` must be ≥40 words.
- `technical_narrative` must NOT contain dollar amounts (regex `\$[\d,]+`).
- `outcome` if present must NOT be a dollar amount.
- `in_playbook_or_bank` validated against database: project name must exist in either the playbook's named-project list or the reviews bank's `project_name` field.

### 5.10 Aggregate financial suppression

Regex + LLM classifier scans full article for:
- Total/aggregate revenue ("$Xm total revenue", "we've earned $X")
- Client concentration ("X% of our clients", "most of our clients in Y")
- Deal metadata ("X deals closed", "average contract value")
- Internal BD metrics ("win rate", "ARPU", "LTV")

Match → strip + flag. `validation.no_aggregate_financial_data = false`.

### 5.11 Stat density cap

Max one supporting number per paragraph. Count digit-bearing tokens that read as statistics. >1 → flag for revision. Soft validator.

### 5.12 Repetition detection

Cross-section: any 8+ word phrase appearing in ≥2 sections → flag. Soft validator.

### 5.13 List formatting

Content enumerating 3+ items MUST render as a list. Detection: "first... second... third" patterns. Flag for conversion at outline stage; block at draft if still prose.

### 5.14 Local entity grounding

If `requires_local_context = true`, `local_entity_grounding.local_context_sentences` must have ≥2 sentences true ONLY of that city. The model is fed a brief on local context from `/data/local_context/{city}.md` reference files (dispatcher seeds these for the priority five cities: Austin, Houston, Dallas, Chicago, LA — via the same import pattern as the playbook). Block ship if missing.

### 5.15 LSI coverage

Compute `lsi_coverage_ratio` after draft. Target ≥ 0.60. Below → flag for revision. Soft validator.

### 5.16 Topic-coverage checklist

Per content type, required sub-topics from the playbook's existing checklist:

- **Cost guide**: cost ranges, drivers, regional variation, team model, maintenance %, timeline, exclusions
- **Comparison guide**: feature table, cost comparison, use-case fit, migration cost, recommendation
- **How-to guide**: prerequisites, numbered steps, pitfalls, tools, outcome

Missing sub-topic on cost guide → block ship. Other content types → flag.

## Phase 6 — Validators (six hard gates)

All run before draft is shippable. Each gates ship; failures surface in review UI with specific reason + `<DataSourceTag>`.

### 6.1 Testimonial validator

For each entry in `testimonials_used`:
- Call `isReviewInBank(brandId, reviewer_name, company, quote_excerpt)`. Must return true.
- Company MUST NOT appear in `getConfidentialCompanies(brandId)`.

Failure → testimonial stripped, `validation.all_testimonials_in_bank = false`. Emit provenance row with `reason = 'validator-stripped'`.

### 6.2 Internal link validator

For each entry in `internal_links`:
- Call `isUrlInLinkTargets(brandId, target_url)`. Must return true.
- Anchor text must appear in `getAnchorVariations(brandId, target_url)` OR be a natural variation not used elsewhere in the same article.

Failure → link stripped, `validation.all_links_in_link_targets = false`. Emit provenance row.

### 6.3 Citation URL validator (HTTP + content match)

For each entry in `statistics_used` AND `external_authority_citations`:
- Fetch URL → require HTTP 200.
- Verify claim's key phrase / numeric value appears in fetched page text (±5% on numbers).

Use the existing OnPage API client from `lib/integrations/dataforseo/onpage.ts` for fetches. Cache 24h.

Failure → claim stripped, `verified_live = false`.

### 6.4 Confidentiality exclusion (dynamic)

Database-driven. Validator scans full article + all schema fields for any company name returned by `getConfidentialCompanies(brandId)`. Currently: Branding Design & Packaging Co, Retail Company. Match → strip + flag. Validators load the exclusion list fresh on every generation — no cached list to go stale.

### 6.5 Aggregate financial suppression

Regex + LLM classifier per Rule 5.10. Strip + flag.

### 6.6 Case-study narrative validator

For each entry in `case_studies_cited`:
- `technical_narrative.length >= 40` words.
- `technical_narrative` does not match `\$[\d,]+`.
- `project_name` exists in either playbook portfolio or `reviews_bank_entries.project_name` for the active brand.

Failure → case study stripped, validation fails.
